# Let's talk modal: beta fixes (November 24, 2026)

Replace the Elementor Custom Code snippet with the new `wl-talk-modal.html`, then clear the page and CDN cache. No changes to buttons, links, HubSpot settings or copy. The previous version is in this folder's git history.

## 1. "Send a message" form doesn't load after a submission

**Cause.** After a submission, HubSpot swaps the form for its own "Display a message" text and never renders that container again. The old code only loaded the embed once per page view, so reopening the modal showed an empty area until the page was reloaded.

**Fix.** One second after a successful submission (behind the modal's thank-you), the script replaces the form container with a fresh, empty one and HubSpot renders a new form into it. If no form appears within 2.5 seconds, the script runs HubSpot's embed script once more. If the modal is reopened before that one second has passed, the reset runs at open. Each new form gets the topic and CTA label of the button that opened it.

## 2. CSS conflicts with the site theme

**Cause.** The site's theme reset (Hello Elementor) styles every `button` with a `#c36` red border and text, and on `:hover` and `:focus` gives it a `#c36` red fill and white text. Those selectors outranked the modal's tab rules, so a hovered tab turned red, and the selected tab (which keeps focus after a click) went white text on white. Elementor's global kit styles also set button and heading fonts.

**Fix.**
- Every modal rule is now scoped to `#wl-talk` (an ID), which outranks theme and Elementor kit selectors. The properties the theme fights over on buttons (font, size, weight, case, color, background, border) also carry `!important`.
- **Tabs:** black text in every state. Hover is a light white wash; the selected tab is a white pill. No red, no white text.
- **Submit button:** Plus Jakarta Sans, 12px, ExtraBold, uppercase with letter spacing, purple `#8754EF` fill, deep purple `#7A41ED` on hover. HubSpot's own form style variables (`--hsf-button__*`, `--hsf-field-input__*` and so on) are set to the same values, so HubSpot's injected styles agree.
- **Red:** the theme's `#c36` no longer reaches any modal element. Form validation uses brand red `#EF4156` for the invalid field's border, and maroon `#661D29` for error text, because brand red fails contrast as text (the brand guide says red is never used for text).
- Close button, "Send a message instead" link and the thank-you buttons are hardened the same way.

## How it was tested

The live beta page can't be reached from the build environment, so the fix was tested in headless Chrome on a test page carrying Hello Elementor's button reset and an Elementor kit font rule, with a stand-in for the HubSpot embed. The old file reproduced both reported problems (red hover tab, white-on-white selected tab, empty form on reopen). The new file showed a working form on reopen, with the new topic pre-selected and a second submission sent, and black tab text in every state.
